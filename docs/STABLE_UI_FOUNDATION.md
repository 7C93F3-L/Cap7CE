# Cap7CE 稳定 UI 共用视觉基础

> 轮次：U1
> 状态：人工确认通过
> 正式界面影响：无；新版根节点只存在于开发服务入口

## 1. 开发入口

从仓库根目录启动：

- `npm run dev:stable-ui`：进入单一、自由缩放的新版开发窗口。

该入口要求实际宿主为 `compatibility`，不新增用户偏好或第三种窗口模式。开发窗口只读写独立的 `window-layout-stable-ui-development.json`，置顶点击只影响本次开发会话，不修改正式 compatibility 布局或用户置顶偏好。关闭开发进程后覆盖立即失效；普通 `npm run dev`、`npm run dev:compatibility` 和打包加载路径继续进入旧 Renderer。

新版开发入口不会在启动时套用 micro / mini / normal 预设，也会旁路旧 resize settle 的自动形态转换和 micro 位置修正。用户拖动只改变 BrowserWindow 的实际 bounds；当前 U1 根节点不根据旧 shellState 切换组件或布局。

## 2. 共用基础

- 新版间距、圆角、文字层级、表面、悬停、选中、标题栏、滚动条和减少动效变量只在 `.cap-stable-ui` 下生效。
- 新版内框表面保留右侧 / 底部 5px 宿主材料间距，使用四角圆角；U1 只显示基础校验卡，不提前建立 U2 主窗口壳层。
- 新版滚动条使用 8px 原生滚动槽与带 2px 透明边界的胶囊滑块，明暗模式分别使用对应文字色透明度；不修改旧 `CustomScrollbar` 的视觉或交互。
- 主窗口和 Preview 的置顶入口共用 `WindowPinButton`，保留 46px 命中宽度、`aria-pressed`、固定 / 取消固定图标及鼠标点击后不残留焦点框的行为。Settings 不装配置顶按钮。
- 标题栏使用 `titlebar-area-*` 安全区域和 Windows 原生 drag / no-drag 语义；最小化、最大化、还原、关闭、系统菜单和 Snap 继续由现有 compatibility 宿主管理。

## 3. 自由缩放边界

新版主窗口采用连续响应式布局。micro / mini / normal 在迁移期只作为旧 Renderer、旧 IPC 和旧快捷动作的兼容名称，不构成新版的三个界面状态。

- U1 不冻结正式预设尺寸，也不要求在两套 300 × 156 契约之间选择。
- 宿主仍保留防止标题栏和关键交互失效的安全最小尺寸；最终数值在正式内容接入并完成 DPI 验证后确定。
- Windows 最大化、还原、系统菜单、标题栏拖动与 Snap 继续由原生 compatibility 宿主管理。
- 如果未来保留窗口尺寸快捷键，它们只能由用户主动触发一次，不得重新引入拖动后的自动切换或强制回弹。

旧 Cap7CE 与旧 compatibility Renderer 继续使用现有稳定状态机；开发旁路不会改变其阈值、布局记录或快捷动作。

## 4. 人工验收清单

1. 在 100%、125%、150% DPI 下连续拖动窗口宽度和高度，确认不会自动回弹或切换旧形态。
2. 确认标题栏拖动、系统菜单、最小化、最大化、还原和 Snap Layouts 正常。
3. 检查 46px 置顶按钮的悬停、点击、图标状态、键盘焦点和系统按钮邻接关系。
4. 检查基础表面在浅色、深色下的 5px 间距、四角圆角、文字可读性和滚动条。
5. 检查从宿主安全下限到普通、最大化和各类 Snap 尺寸之间的任意中间状态；U1 校验卡应始终保持可滚动和可读。
6. 普通旧 Cap7CE、普通 compatibility 主窗口和旧 Preview 应无变化，旧界面拖动仍遵循其既有状态机。

U1 人工确认只判断开发隔离、自由缩放和共用视觉基础是否成立，不决定最终窗口预设、最小尺寸或快捷键去留。
