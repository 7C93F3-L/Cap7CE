# Cap7CE skim 与多格式接入执行规划

> 文档状态：历史执行路线；主要轮次已在 0.8.0 / 0.8.1 落地，剩余工作转入 `REMAINING_CAPABILITY_ROADMAP.md`
> 基线版本：0.7.8
> 更新日期：2026-08-03
> 内部名称：`skim`
> 中文名称：轻阅
> 英文名称：Skim

## 1. 文档目的

本文用于安排 Cap7CE 后续“轻阅、目录添加、多格式浏览与搜索、独立缓存和内容预览”工作的实施顺序。

它负责：

- 记录已经确认的产品边界；
- 划分阶段和每轮开发目标；
- 明确各轮包含与暂不包含的内容；
- 保留未来能力的扩展接口；
- 作为每次开始新任务时的范围基准；
- 避免目录、索引、缓存、预览和窗口状态在同一轮中无边界扩张。

它不替代具体阶段的实施规格。某一轮开始前，如果涉及 SQLite、文件扫描、缓存、跨进程或预览架构，应先依据当前代码补充必要的技术设计与验收案例。

执行过程中允许根据真实难度、用户验证结果和新增需求调整轮次。调整时优先保持每一轮目标独立、改动范围可验证，不为了维持原轮次编号而强行合并高风险工作。

## 2. 总体产品方向

整体工作按以下顺序推进：

1. 接入 skim 基础浏览、定位与目录添加能力；
2. 将多种项目关联文件接入 skim；
3. 将白名单多格式文件接入已添加目录和现有基础搜索；
4. 建立 skim 独立缩略图和预览缓存，并逐步实现非视觉文件内容预览；
5. 软件交互和多格式链路稳定后，再单独规划搜索系统大升级。

核心产品关系：

```text
正式搜索
  面向已添加目录
  负责快速检索、筛选、预览和调用日常文件

skim
  面向本机磁盘和临时浏览位置
  负责逐层浏览、快速定位和添加搜索目录

目录添加
  将 skim 中发现的目录纳入正式搜索范围
```

Cap7CE 不以替代 Windows 资源管理器或建立全盘后台索引为目标。

路径语义、目录意图、全文检索、OCR、多来源证据汇总和模型辅助搜索不属于本执行规划。相关构想与研究边界见：

`docs/SEARCH_ENHANCEMENT_RESEARCH_PLAN.md`

## 3. 已确认的产品边界

### 3.1 正式搜索与 skim 分离

进入 skim 后：

- 不继承或应用正式搜索词；
- 首期直接显示本机磁盘列表；
- 首期不提供 skim 内关键词搜索；
- 首期不提供 skim 内格式筛选和文件排序；
- 不因为浏览行为写入正式索引；
- 不触发 AI 识别；
- 不递归扫描尚未进入的目录；
- 不自动将浏览位置添加为正式目录。

正式搜索现场可以作为返回上下文保留，但不会控制 skim 的显示内容。

当用户从无结果搜索进入 skim、找到目录并完成添加后，可以选择返回正式搜索并重新执行进入前的查询。

未来可能增加：

- skim 内当前一级筛选；
- 指定目录及子目录的临时定位搜索；
- skim 格式筛选；
- skim 排序；
- 添加磁盘根目录；
- skim 与已添加目录的组合搜索。

这些能力首期不实现，但状态、条目、范围和服务接口不得将其永久封死。

### 3.2 skim 入口与界面

skim 有两个入口：

1. 正式搜索无结果时，点击结果提示区域；
2. 右侧控制栏设置图标上方的 skim 图标。

skim 图标：

- 显示条件与设置入口一致；
- capsule 和 micro 不显示；
- 实际窗口高度达到标准 mini 高度及以上时显示；
- 不新增主进程窗口状态；
- skim 作为 Renderer 视图进入现有主窗口壳层。

skim 首期导航：

```text
磁盘列表 -> 当前磁盘 -> 文件夹 -> 子文件夹 -> 文件
```

进入 skim 后，结果页现有顶部标签区域替换为面包屑。面包屑复用当前标签系统的视觉、点击和动效，不另建传统文本路径栏。

首期每次进入 skim 都从磁盘列表开始，不记忆上次浏览位置。

### 3.3 skim 目录读取

浏览只读取当前目录的直接子项，不预先递归读取后代。

读取要求：

- 使用异步读取；
- 支持任务 ID 或取消令牌；
- 离开目录后忽略旧读取结果；
- 不申请管理员权限；
- 无权限、目录不可用、读取失败和普通限制通过搜索框临时反馈；
- 不能因大目录导致主窗口假死、闪退或长时间无响应；
- 不跟随可能造成循环的符号链接或目录链接。

磁盘根目录首期只能进入，不允许添加。

“磁盘根目录暂不允许添加”是当前策略，而不是不可变的数据结构限制。未来如需开放，应可以通过修改验证策略和风险提示接入。

### 3.4 目录添加

Settings、主界面拖入、skim 和未来其他入口必须复用同一套目录添加服务。

添加服务接收一组候选项目，而不是只接受一个文件夹路径。

候选转换：

- 文件夹转换为自身路径；
- 文件转换为其直接所在目录；
- 多个文件位于同一目录时只保留一个目录候选；
- 路径统一规范化并按 Windows 大小写不敏感规则去重；
- 磁盘根目录候选按当前策略过滤；
- 无效候选不会阻止其他有效候选继续添加。

例如同时选中：

- `D:\123` 文件夹；
- `D:\abc.png` 文件。

候选为 `D:\123` 与 `D:\`。过滤磁盘根目录后，仍正常添加 `D:\123`。

重复与包含关系：

- 完全相同目录不重复添加；
- 子目录已被现有父目录覆盖时，返回“已包含”结果；
- 新目录包含现有若干子目录时，返回结构化冲突结果；
- 需要用户决定合并或替换时，使用界面内确认弹层；
- 目录扫描与搜索结果不得因父子目录重叠产生重复结果。

批量添加最终需要支持：

- 仅多选文件夹：添加全部选中文件夹；
- 仅多选文件：添加它们的直接所在目录并去重；
- 同级混合选择文件夹和文件：文件所在目录参与包含归并；
- 无效磁盘根目录候选被忽略，其他有效目录继续处理。

首期如暂未接入全部批量交互，底层服务仍应从一开始使用集合输入和结构化结果，避免后续重做。

### 3.5 skim 选择、右键与打开

磁盘列表：

- 支持双击进入；
- 首期不显示右键菜单。

文件夹和文件共用一套 skim 右键菜单样式与菜单结构：

1. 添加目录；
2. 预览；
3. 打开；
4. 打开路径。

动作语义：

| 动作 | 文件夹 | 文件 |
| --- | --- | --- |
| 添加目录 | 添加该文件夹 | 添加文件的直接所在目录 |
| 预览 | 显示文件夹信息与统计 | 支持内容预览时显示内容，否则显示文件信息 |
| 打开 | 在 skim 中进入文件夹 | 使用系统默认应用打开 |
| 打开路径 | 在资源管理器中定位文件夹 | 在资源管理器中定位文件 |

多选规则：

- 多选预览和多选打开只作用于最后点击的活动项目；
- 多选打开路径只打开当前 skim 路径，不为每个项目创建资源管理器窗口；
- 多目录添加按目录添加服务的集合规则执行；
- Ctrl / Shift 多选继续支持多文件拖出。

首期不提供：

- 删除；
- 复制；
- 移动；
- 重命名；
- 新建文件或文件夹。

### 3.6 文件与文件夹信息预览

统一预览外壳支持不同 Preview Provider。

基础 Provider 方向：

```text
PreviewController
├─ FolderInfoPreview
├─ FileInfoPreview
├─ ImagePreview
├─ FutureTextPreview
├─ FutureAudioPreview
└─ FutureVideoPreview
```

暂不支持内容预览的文件显示：

- 文件名；
- 完整路径；
- 文件格式；
- 修改时间；
- 文件大小。

文件夹预览显示：

- 文件夹名称；
- 完整路径；
- 修改时间；
- 是否位于已添加目录范围；
- 全部可访问后代文件数量；
- 全部可访问后代文件夹数量；
- 全部可访问后代文件总大小；
- 实时统计状态。

文件夹统计：

- 由用户按空格或菜单“预览”显式触发；
- 统计全部可访问普通后代文件，不受 skim 文件格式白名单限制；
- 不读取文件内容；
- 不写入正式索引；
- 不生成缩略图或 AI 任务；
- 不跟随符号链接或目录链接；
- 无权限项目跳过；
- 使用异步、小批量、受控并发方式遍历；
- 进度更新需要节流，避免频繁 IPC 和 Renderer 更新；
- 再次按空格、点击预览窗口收缩/关闭、切换项目、退出 skim 或关闭窗口时立即取消；
- 取消后停止领取新任务并忽略迟到结果。

已提交给操作系统的单次文件系统调用不保证在内核层瞬间中断，但 UI 必须立即关闭，任务不得继续扩展遍历范围。

### 3.7 搜索框临时反馈

搜索框承担普通临时反馈，不新增无必要弹窗。

适用内容包括：

- 已添加目录数量；
- 重复目录；
- 已被父目录包含；
- 部分候选被忽略；
- 磁盘根目录暂不允许添加；
- 无权限；
- 目录不可用；
- 目录读取失败；
- skim 缓存清理结果；
- 其他无需用户作出选择的成功或失败提示。

临时反馈：

- 不写入真实搜索内容；
- 显示数秒后消失；
- 系统反馈优先于闲置操作提示；
- 消失后恢复原搜索词或操作提示。

快捷指令的 `y / n` 确认继续只服务快捷指令。

普通功能中凡是必须由用户明确确认或取消的操作，使用界面内确认弹层。删除、覆盖、缓存清理等高风险操作不得借用快捷指令确认态。

### 3.8 多格式能力

“能够浏览”“能够正式搜索”“能够生成缩略图”“能够预览”“能够 AI 识别”必须分开表达。

建议中央能力定义至少包含：

- `canBrowse`
- `canSearch`
- `canThumbnail`
- `previewKind`
- `canAIIndex`

首期非视觉文件：

- 可以在 skim 中显示；
- 可以打开；
- 可以打开路径；
- 可以拖出；
- 不立即进入正式搜索；
- 不进入 AI 识别；
- 暂不支持内容预览时使用文件信息预览。

后续多格式正式搜索主要服务已添加目录。

### 3.9 skim 缓存

skim 生成的缩略图、预览图和元数据使用独立持久缓存，不与正式搜索缓存混合。

建议逻辑结构：

```text
skim-cache/
├─ thumbnails/
├─ previews/
└─ metadata/
```

规则：

- 当前目录可见视觉文件按需生成缩略图；
- 不递归为未进入的后代目录生成缩略图；
- 离开目录后停止领取新的缩略图任务；
- 显式空格预览优先于缩略图后台任务；
- 缓存键包含源路径、文件大小、精确修改时间和内部渲染版本；
- 源文件变化后不错误复用旧缓存；
- 浏览和预览不写正式索引、不触发 AI；
- skim 缓存不进入【自动优化】；
- 文件即使已位于正式添加目录，只要从 skim 触发生成，仍写入 skim 缓存；
- 不在加入正式目录后迁移 skim 缓存；
- 用户不清理时持续保留，以改善再次浏览体验。

Settings【缓存管理】后续新增：

> 清理 skim

该操作统一清理：

- skim 缩略图；
- skim 预览图；
- skim 元数据。

它不影响正式搜索缩略图、正式预览图或模型输入缓存。

## 4. 扩展性原则

首期不实现的功能不提前展示空壳控件，但应保留合理的扩展边界。

建议方向：

### 4.1 通用 skim 状态

`SkimState` 应能容纳：

- 当前路径；
- 面包屑；
- 未来查询词；
- 未来格式筛选；
- 未来排序字段和方向；
- 当前选中项；
- 活动项目；
- 滚动位置；
- 当前目录读取任务。

首期未使用的字段可后续增加，不要求一次全部持久化。

### 4.2 通用文件条目

skim 不应继续使用只适合图片结果的条目类型。

通用条目需要能够表达：

- drive / folder / file；
- 路径、名称、扩展名、大小和时间；
- 是否位于已添加目录范围；
- 缩略图和预览能力；
- 正式搜索和 AI 能力；
- 当前临时状态和错误。

### 4.3 通用范围描述

正式搜索范围和 skim 浏览范围首期保持分离，但范围模型不应把二者写死为永远不能组合。

未来如确有必要，可以增加：

- 已添加目录范围；
- 当前 skim 路径范围；
- 明确的组合范围。

组合搜索大概率不实施，因此首期不得为它增加额外业务复杂度；只需避免通过不可扩展类型把道路封死。

### 4.4 可复用 UI

- skim 入口复用现有右侧控制栏；
- 面包屑复用标签系统；
- skim 菜单复用现有菜单视觉；
- 文件卡片复用现有网格、选择、滚动和拖拽基础；
- 预览继续复用独立 PreviewWindow 外壳；
- 普通临时反馈复用搜索框系统反馈通道。

不得为了 skim 新增平行窗口状态机、第二套菜单视觉或第二套提示系统。

## 5. 阶段与执行轮次

规划基线为 8 轮开发。某一轮如果实际风险或改动量超出安全范围，可以拆分为 A / B 两轮；相邻轮次只有在范围足够小且验证清晰时才合并。

### 第一阶段：skim 基础能力

#### 第 1 轮：统一目录添加服务

目标：

- 为 Settings、skim、拖入和未来入口建立唯一的目录添加底层能力。

包含：

- 集合输入；
- 文件和文件夹候选转换；
- 磁盘根目录策略过滤；
- 路径规范化与去重；
- 父子目录包含检测；
- 多候选归并；
- 结构化成功、忽略、冲突和失败结果；
- 搜索框临时反馈接入；
- 必须由用户选择时接入确认弹层；
- 目录添加服务测试。

不包含：

- skim UI；
- 拖入主界面交互；
- 正式多格式索引。

#### 第 2 轮：skim 外壳与逐层浏览

目标：

- 建立可进入、可退出、不会影响现有窗口状态机的 skim 基础视图。

包含：

- 无结果提示区域入口；
- 右侧控制栏 skim 入口；
- 磁盘列表；
- 双击进入；
- 当前一级目录读取；
- 读取取消与迟到结果保护；
- 面包屑；
- 返回与退出；
- 正式搜索现场恢复；
- 普通读取错误使用搜索框反馈；
- 未来查询、格式和排序的状态扩展边界。

不包含：

- skim 内搜索；
- 格式筛选；
- 排序；
- 临时缩略图；
- 非视觉内容预览。

#### 第 3 轮：skim 选择、操作与信息预览

目标：

- 完成 skim 中定位、选择、添加和调用文件的基础闭环。

包含：

- 单选、Ctrl 多选和 Shift 范围多选；
- 活动项目规则；
- 文件夹和文件共用的 skim 右键菜单；
- 添加目录；
- 打开；
- 打开路径；
- 多文件原生拖出；
- 空格预览入口；
- 文件信息预览；
- 文件夹信息预览；
- 全部后代异步统计；
- 实时统计更新；
- 空格、预览控制栏、项目切换和退出时取消；
- 多选打开、预览和打开路径规则。

不包含：

- 删除；
- 文件管理操作；
- skim 内容缩略图；
- 文本、音频和视频内容预览。

### 第二阶段：多格式接入

#### 第 4 轮：多格式浏览接入 skim

目标：

- 让项目关联非视觉文件可以在 skim 中看到、定位、打开和拖出。

包含：

- 中央格式能力表；
- skim 白名单；
- 通用 SkimEntry；
- 文件夹、视觉文件和非视觉文件混合网格；
- skim 图标资产整理与命名空间；
- 格式卡片和通用文件兜底；
- 不支持内容预览的文件使用信息预览；
- 格式能力测试。

不包含：

- 非视觉文件正式搜索；
- 非视觉 AI；
- Office、3D 或媒体内容解析；
- skim 缩略图缓存。

#### 第 5 轮：多格式正式索引基础

目标：

- 为已添加目录建立通用文件目录记录，同时保护现有视觉识别链路。

包含：

- 通用文件扫描记录；
- 通用文件目录或索引基础层；
- 名称、扩展名、文件存在状态和目录归属等基础字段；
- 文件存在状态和目录归属；
- 非视觉文件明确不进入 AI 任务；

## 6. 每轮开始时的固定流程

每次开始一轮工作前：

1. 明确本轮编号和唯一目标；
2. 检查用户是否对本规划做了动态调整；
3. 阅读 `CHANGELOG.md` 和 `docs/SOFTWARE_ARCHITECTURE.md`；
4. 检查 `git status --short`；
5. 保留用户已有和无关修改；
6. 对涉及搜索、SQLite、缓存、扫描或跨进程的轮次先核对真实调用链；
7. 必要时先补充该轮实施规格和验收案例；
8. 不提前实现下一轮功能。

## 7. 每轮完成时的固定验证

代码修改完成后：

1. 运行与改动对应的自动测试；
2. 运行 `npm run build`；
3. 运行 `git diff --check`；
4. 检查 `git status --short`；
5. 汇总修改文件和真实验证结果；
6. 明确哪些交互和视觉效果仍需用户手动验证；
7. 未运行 `npm run pack` 时不得声称安装包验证通过；
8. 用户确认后再提交；
9. 独立功能或修复使用独立提交，除非用户明确要求覆盖提交。

## 8. 动态调整规则

执行过程中出现以下情况时允许调整规划：

- 实际代码依赖与规划假设不一致；
- 单轮同时触及过多高风险模块；
- 用户验证发现交互方向需要修正；
- 新功能会破坏现有稳定窗口或预览行为；
- 数据迁移风险高于预期；
- 某项暂缓能力成为后续阶段的真实阻塞；
- 某两个相邻轮次实际非常小且可以安全合并。

调整原则：

- 先说明原因和影响；
- 优先拆小，不扩大单轮范围；
- 不因为未来设想提前实现当前不需要的功能；
- 不通过只适合首版的硬编码封死未来扩展；
- 已确认的用户数据、正式索引和缓存边界不得静默改变；
- 规划变化不等于自动获得提交、发布或高风险迁移授权。
