# Cap7CE 稳定 UI 左侧栏与目录接入

> 轮次：U4  
> 状态：人工确认通过  
> U4 当时仅通过开发入口验收；D0 后由正式 `stable` 模式复用同一侧栏业务链，见 `docs/STABLE_UI_DEFAULT_HOST.md`

## 1. 单一状态与事务

新版左侧栏只接收 `App.tsx` 提供的受控状态和动作，不直接访问 preload API，也不保存第二份搜索、AI 或目录业务状态。AI 增强继续进入现有任务控制器；排序、查看范围和目录选择继续更新正式 `SearchState`，结果刷新仍由既有搜索链执行。

目录加载、系统选择添加、拖入确认、冲突替换、重命名、删除、文件数刷新和服务不可用反馈继续由现有目录事务与确认面板负责。新版组件只展示目录并发出用户意图，不修改目录服务、SQLite、扫描范围或目录归属语义。

## 2. 左侧栏行为

- AI 增强、排序和查看范围显示真实状态，并调用与旧界面相同的动作。
- “全部目录”和单目录使用正式目录列表、文件数与选择状态；长名称保持单行省略，完整路径和文件数通过悬停标题提供。
- 标题栏加号打开现有系统目录选择；双击目录名称进入行内重命名；右键或末尾管理按钮可重命名、删除。
- 目录从资源管理器拖入新版窗口时继续经过现有添加确认与冲突替换面板，不绕过原生文件拖出抑制。
- 侧栏宽度仍只保存在当前 Renderer 会话；拖到紧凑宽度后隐藏文字并保留 40px 图标栏。
- 底部 Skim 与 Settings 始终锚定在侧栏底部；展开时横排，紧凑时竖排。

## 3. 后续轮次边界

U4 的 Skim 按钮只切换 U2 的占位插槽，真实导航、地址栏和文件网格仍留在 U5。Settings 按钮暂时调用现有统一打开动作并显示旧设置页；独立 Settings 窗口宿主和正式内容分别留在 U6、U7。以上临时回落不建立第二套设置读写事务。

新版左侧栏样式由 `StableSidebar.css` 独立持有，主响应式网格继续由 `StableMainShell.css` 持有。架构守门记录所有新增侧栏模块的当前体量，并把 `App.tsx` 上限从 3334 行降到 3330 行。

## 4. 人工验收清单

1. 分别检查 0、1、多个目录，确认加载、空状态、全部目录、文件数与当前选择正确。
2. 检查长目录名省略与悬停信息；切换目录后确认结果和顶部统计随正式搜索刷新。
3. 使用加号添加目录、从资源管理器拖入目录，并覆盖无冲突、需要替换和取消三条确认路径。
4. 双击重命名，测试 Enter 保存与 Esc 取消；通过右键或管理按钮删除目录并确认结果回到全部目录。
5. 切换 AI 增强、排序字段 / 方向和三种查看范围，确认状态、反馈与结果同步。
6. 将左栏拖到 40px，再恢复到展开宽度；检查图标、悬停 / 选中胶囊、目录滚动和底部按钮排列。
7. 将窗口高度调整到约 360px，检查目录列表独立滚动，Skim 与 Settings 按钮始终可达。
8. 点击 Skim，确认目前只切换占位区；点击 Settings，确认进入现有设置页并可正常返回新版结果页。

U4 人工确认不包含真实并排 Skim、独立 Settings 窗口、最终 Acrylic 材质或窗口预设与快捷动作收口。
