# Cap7CE 稳定 UI 搜索与结果接入

> 轮次：U3
> 状态：人工确认通过
> 正式界面影响：无；仍仅通过 `npm run dev:stable-ui` 进入

## 1. 单一业务权威

新版入口不保存第二份查询、结果、选择、滚动、Preview 或文件操作状态。`App.tsx` 继续持有正式搜索编排，通过展示适配边界把受控输入、结果状态和正式 `ResultsView` 交给新版根节点。普通旧界面继续使用同一组状态与动作。

顶部输入只负责文字输入、中文 IME composition 和提交事件。查询、快捷指令、`7ce/` AI 请求、绝对目录路径解析、清空查询后的默认搜索、任务取消及失败反馈继续进入原 `submitSearch` / `runSearch` 链。

## 2. 正式结果能力

- 中央内容区直接使用现有 `ResultsView`、`VirtualImageGrid`、缩略图和证据分组，不复制网格或缓存逻辑。
- 单选、Ctrl 多选、Shift 连选、方向键、Esc 清除、滚动记忆和 Preview 返回定位保持原行为。
- 双击打开、空格 Preview、长按空格关键词编辑、右键菜单、原生文件拖出、路径 / 文件复制、目录定位和回收站删除继续调用正式动作。
- 高度低于 360px 时仅把正式虚拟网格切到既有横向算法；其他尺寸使用 normal 网格算法。该选择来自视口媒体条件，不读写 micro / mini / normal 窗口状态。
- 右侧 Skim 仍是 U2 占位内容；空间不足时隐藏结果区只影响显示，不另建查询状态。

## 3. 迁移隔离

新版根节点不直接访问 preload API，也不依赖 `App.tsx`。开发入口同时动态加载正式 App 状态权威和新版展示根节点，再通过显式 Props 组合；生产入口与普通开发入口继续只渲染旧界面。

全局窗口形态快捷入口、左侧目录筛选、Settings 和真实 Skim 不在 U3 接入。开发入口收到旧窗口形态激活通知时只恢复搜索框焦点，不触发尺寸或组件树切换。

## 4. 人工验收清单

1. 输入普通中英文关键词、快速连续输入和中文 IME，确认 composition 期间不会提前提交，Enter 后结果正确。
2. 清空已有查询，确认立即恢复默认全部文件；测试快捷指令、`7ce/` 和有效 / 无效目录路径反馈。
3. 检查大量混合格式结果、证据分组、纵向滚动和低于 360px 时的横向滚动及位置保持。
4. 检查单选、Ctrl / Shift 多选、方向键、Esc、双击打开、空格短按 Preview 和长按关键词编辑。
5. 检查右键 Preview / 打开 / 定位 / 复制路径 / 编辑关键词 / 删除，以及 Ctrl+C 文件复制和原生拖出。
6. 在窄窗、最大化和 Windows Snap 下反复打开 / 隐藏 Skim 占位区，确认搜索任务、选择和滚动状态不被销毁。
7. 启动普通旧界面，确认原搜索胶囊、网格方向、窗口状态快捷键和 Skim / Settings 入口无变化。
8. 点击 Windows 原生关闭按钮，确认空闲窗口进入既有 standby / line 隐藏链，而不是停留在原地；再从现有入口恢复窗口，确认查询、选择和滚动状态仍保留。

U3 人工确认不包含左侧栏真实目录操作、真实并排 Skim、最终 Acrylic 宿主或窗口预设收口。
