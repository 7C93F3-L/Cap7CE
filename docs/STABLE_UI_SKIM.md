# Cap7CE 稳定 UI 并排 Skim 接入

> 轮次：U5
> 状态：人工确认通过
> 正式界面影响：无；仍仅通过 `npm run dev:stable-ui` 进入

## 1. 单一 Skim 权威

稳定 UI 不创建第二份路径、目录结果、缩略图会话、排序或查看范围状态。`App.tsx` 中现有的 `useSkimReadController` 继续是唯一读取控制器，并同时向旧 Skim 页面和新版右侧面板提供正式状态与动作。

新版面板直接嵌入现有 `SkimView`，只在嵌入模式下移除旧搜索胶囊。虚拟网格、目录与文件缩略图、Preview、内容预览、右键菜单、打开 / 定位 / 复制、原生拖出、添加目录、收藏或移出侧栏继续走原实现；稳定 UI 组件不直接读取 preload API。

## 2. 面板与导航

- Skim 默认宽度为 360px，可在 280–480px 内拖动，双击分隔线恢复 360px；右侧和底部继续保留 5px 内框间距。
- 返回动作只进入父级；位于“此电脑”时保持面板打开，不切换 `activeView` 或关闭搜索结果。
- 地址栏显示可点击的“此电脑”和路径面包屑；双击地址栏可输入完整路径，Enter 打开，Esc 取消，空输入返回“此电脑”。路径字符只用于本次明确导航，不提前实现未来的 Skim 内搜索。
- Skim 排序使用独立的 `skimSortPreference`，查看范围使用 `skimDisplay.mode`；两者不改写结果区的排序与 `skimDisplay.searchMode`。
- 面板开关只控制显示。隐藏时不卸载正式 Skim 组件，不清空路径、选择或滚动位置，并停止隐藏视图的全局文件快捷键监听。

## 3. 连续响应式边界

宽度不足时，打开的 Skim 可以在视觉上替换结果区；结果组件仍保持挂载，查询、选择和滚动记忆不会因此销毁。高度低于 360px 时隐藏侧栏与 Skim 工具栏，同一个正式虚拟网格使用既有横向布局算法；其余高度使用 normal 网格算法。以上布局只读取视口条件，不写入或推断 micro、mini、normal 窗口状态。

U5 完成时 Settings 仍进入现有设置页。U6 已把稳定 UI 开发入口切到独立 Settings 窗口宿主；正式设置内容仍属于 U7，本文不把后续状态回写为 U5 产物。

## 4. 人工验收清单

1. 启动稳定 UI，确认搜索结果与真实 Skim 在宽窗中同时可见，右侧显示本机真实磁盘或目录内容。
2. 点击侧栏 Skim 按钮反复隐藏 / 打开，确认当前路径、选择和滚动位置保留，隐藏期间文件快捷键只作用于可见结果区。
3. 从“此电脑”进入磁盘和多级目录，检查返回、各级面包屑和“此电脑”按钮；在根级点击返回不应关闭面板。
4. 双击地址栏，测试有效完整路径、无效路径反馈、Enter 打开、Esc 取消和空路径返回“此电脑”。
5. 分别切换 Skim 的名称 / 时间、升 / 降序以及默认 / 全部 / 自定义查看范围，确认右侧变化但中央结果排序和范围不被改写。
6. 检查目录与文件缩略图、双击打开、空格 Preview、右键 Preview / 打开 / 定位 / 复制路径 / 添加目录 / 加入或移出侧栏、Ctrl+C 和原生拖出。
7. 将 Skim 拖到 280px、480px并双击恢复 360px；检查右侧与底部 5px 间距、地址省略、工具按钮和滚动条。
8. 检查窄窗、极窄窗、低于 360px、高窗、最大化和 Windows Snap；确认内容连续重排，没有强制窗口尺寸或未知状态切换。
9. 运行普通旧界面，确认原独立 Skim 页面、搜索胶囊、快捷键和窗口状态语义没有变化。

U5 人工确认不包含独立 Settings 窗口、最终 Acrylic 宿主、默认窗口尺寸收口或窗口预设快捷键去留。
