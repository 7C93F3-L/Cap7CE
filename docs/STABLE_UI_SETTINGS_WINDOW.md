# Cap7CE 稳定 UI 独立 Settings 窗口宿主

> 轮次：U6
> 状态：人工确认通过
> 正式界面影响：无；仍仅通过 `npm run dev:stable-ui` 进入

## 1. 宿主与回退边界

稳定 UI 的 Settings 按钮、全局快捷动作、托盘菜单、通知点击和 Preview 入口统一调用同一个打开动作。稳定 UI 开发入口启用时，该动作只创建或恢复独立 Settings `BrowserWindow`；旧 Cap7CE 外壳继续进入主窗口内的原 Settings 页面。两种宿主不会同时打开，旧设置内容和临时编辑事务没有被复制到新窗口。

独立 Settings 使用专用 Renderer 入口和 U6 宿主占位内容，不导入现有 `SettingsView`，也不提前接入保存、更新下载、快捷键捕获、目录任务或其他 U7 设置能力。关闭按钮只隐藏 Settings 自身，主窗口和 Preview 保持存在，搜索、Skim、选择与滚动状态不会被切换。

## 2. 单实例与布局记忆

`SettingsWindowController` 独占窗口创建、加载、显示、聚焦、隐藏和退出销毁生命周期。重复打开已存在窗口时只执行还原、显示和聚焦；窗口最小化或隐藏后也不会创建第二个实例。

Settings 使用独立的版本 1 布局文件，不读取或写入 normal 记录。移动与缩放停止后保存完整 bounds、显示器 ID、显示器 / work area 快照和缩放比例；冷启动或隐藏后重开时按保存显示器恢复，显示器缺失或工作区变化时复用公共几何规则映射并夹回可见区域。默认尺寸为 `860 × 680`，最小尺寸为 `620 × 480`。

## 3. 当前视觉边界

U6 只建立窗口宿主，暂时继承稳定 UI 开发入口当前 compatibility / WCO 的窗口材质与 36 DIP 系统标题栏策略。最终 Acrylic 材质、标题栏高度、完整 Settings 布局与细节仍按后续视觉收口轮处理；本轮不把宿主占位页当作最终设计。

## 4. 人工验收清单

1. 运行 `npm run dev:stable-ui`，点击左下 Settings，确认出现独立窗口，主窗口内容和滚动位置保持不变。
2. 连续点击 Settings 按钮、快捷键、托盘 Settings 和通知入口，确认始终只有一个 Settings，已有窗口会恢复并聚焦。
3. 保持 Preview 打开，再从 Preview 进入 Settings，确认主窗口、Preview 和 Settings 可以同时存在。
4. 点击 Settings 原生关闭按钮，确认只隐藏 Settings；再次打开应恢复同一窗口实例。
5. 移动并缩放 Settings，关闭后重开以及重启开发任务，确认位置和尺寸恢复；在双屏间移动并测试移除原显示器后的可见恢复。
6. 运行普通旧界面，确认 Settings 仍使用原主窗口页面，不会同时打开独立窗口。

更新下载、快捷键捕获与全部正式设置内容的交互验收属于 U7；U6 只确认这些能力没有被复制或提前接入。
