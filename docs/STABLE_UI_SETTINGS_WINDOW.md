# Cap7CE 稳定 UI 独立 Settings

> 轮次：U6 宿主 + U7 正式内容
>
> 状态：U7 自动验证与人工确认通过
>
> 正式界面影响：无；仍仅通过 `npm run dev:stable-ui` 进入

## 1. 宿主与回退边界

稳定 UI 的 Settings 按钮、全局快捷动作、托盘菜单、通知点击和 Preview 入口统一调用同一个打开动作。稳定 UI 开发入口启用时，该动作只创建或恢复独立 Settings `BrowserWindow`；旧 Cap7CE 外壳继续进入主窗口内的原 Settings 页面。关闭按钮只隐藏 Settings 自身，主窗口、Preview、搜索、Skim、选择和滚动状态保持不变。

`SettingsWindowController` 独占窗口创建、加载、显示、聚焦、隐藏和退出销毁生命周期。Settings 继续使用独立版本 1 布局文件，默认尺寸 `860 × 680`、最小尺寸 `620 × 480`；记录不会写入 normal 布局，也不会触发 micro / mini / normal 自动形态切换。

## 2. U7 内容与状态边界

独立 Renderer 按通用、外观、浏览与 Skim、搜索与 AI、缓存与索引、快捷键、诊断、关于八类组合正式内容，并提供当前语言下的本地条目筛选。新版较详细的分类和说明作为当前文案方向；旧版存在而新版原型未逐项对应的正式能力补入合适分类。未冻结的新旧增删改和遗漏项允许在后续使用中继续调整，不要求 U7 一次性锁定最终文案清单。

页面直接调用现有偏好、目录、缓存、嵌入元数据、快捷键、诊断、llama.cpp、模型和应用更新 IPC，并复用既有复杂设置行。`useSettingsWindowController` 只组合显示状态，不建立第二份 Store 或后台任务；`settingsDataBroadcast.ts` 将偏好与目录的正式结果同步给主 Renderer 和 Settings Renderer，任一入口修改后另一入口不必重开才能获得新状态。

目录选择对话框以实际发起请求的 BrowserWindow 为父窗口。目录冲突替换、删除、两类缓存清理和快捷键占用仍沿用原确认、授权与回滚语义；更新下载、运行时启停、模型选择和诊断导出仍由既有服务执行。

## 3. 当前视觉与窗口材质边界

U7 先完成正式内容和响应式布局，不把细节样式当作最终 U11 收口结果。窗口继续继承 U6 当前 compatibility / WCO 宿主和 36 DIP 系统标题栏策略。

“窗口材质”确认是后续需要新增的正式功能。U7 只显示 `Acrylic（目标，只读）`，不声称当前宿主已经切换为 Acrylic，不提供无效选择，也不提前修改 BrowserWindow 材质；真实能力和最终默认尺寸、标题栏及视觉细节留给规划中的后续窗口 / 视觉轮。

## 4. U7 人工验收清单

1. 运行 `npm run dev:stable-ui`，打开 Settings，确认左侧八个分类、搜索框和各分类正式内容均可见；缩放窗口时内容连续重排，没有固定尺寸强制回弹。
2. 搜索一个设置标题或说明中的中英文词，确认只显示匹配分类 / 条目；清空后恢复当前分类。
3. 修改语言、主题、通知、提示、AI、line 等安全偏好，确认主窗口无需重启即可同步；从旧入口修改后重新查看独立 Settings，也应同步。
4. 添加、重命名和删除测试目录，确认系统目录选择框位于 Settings 前方，冲突和删除均需确认，主窗口目录列表同步。请勿使用需要保留的唯一目录做删除测试。
5. 检查 Skim 显示、运行时 / 模型、缓存统计与清理、快捷键捕获、诊断和版本更新；确认操作沿用现有任务状态、禁用条件和错误反馈。
6. 确认“窗口材质”仅显示 Acrylic 目标只读状态；它不改变当前窗口材质。切换窗口呈现模式仍属于既有受控重启功能。
7. 点击原生关闭按钮后再次打开 Settings，确认窗口只隐藏并恢复同一实例，位置和尺寸记忆仍有效；主窗口与 Preview 不受影响。
8. 运行普通旧界面，确认旧 Settings 仍可用，不会同时打开独立窗口。
